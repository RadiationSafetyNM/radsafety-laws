# 법령 개정 시 실제로 달라지는 것 — 데이터 모델 조사

> 2026-07-31 실측. 목적: 개정 감지 스크립트가 **무엇을 신호로 삼아야 하는가**를 데이터로 정하기 위함.
> 관찰 대상 = 우리 저장소 git 이력(2026-06~07) + law.go.kr OpenAPI 라이브 조회.

---

## 0. 요약 — 신호로 쓸 것 / 쓰면 안 되는 것

| 층 | ✅ 신호로 쓸 것 | ✖ 쓰면 안 되는 것 |
|---|---|---|
| 법령 본문 | `법령MST` 변경 | 파일 diff (미러 재가공 포함) |
| 조문 | 조 단위 해시 비교 | 라인 diff |
| 별표·서식 | **원본(hwp/hwpx) 파일 해시** | **`flSeq` 링크 변경** · PDF 해시 |
| 고시 | `행정규칙일련번호` 변경 | (미구현) |

**두 함정이 결정적이다** — 아래 §3-1, §3-2.

## 1. 법령 본문이 개정될 때

실측: 원자력안전법 시행규칙, 2026-07-09 공포(커밋 `4abdd2a`).

### 1-1. frontmatter — 4개 필드가 바뀐다

```diff
-법령MST: 282129          +법령MST: 288077        ← 버전키(개정마다 신규 발급)
-공포일자: 2025-12-29      +공포일자: 2026-07-09
-공포번호: '02067'         +공포번호: '02132'
-시행일자: 2026-01-01      +시행일자: 2026-07-09
```

`법령ID`(011880)는 **불변**. 그래서 ID = 법 자체, MST = 그 법의 이번 판.

### 1-2. 조문 본문 — 개정 흔적이 텍스트로 남는다

| 표기 | 전량 집계 | 의미 |
|---|---|---|
| `<개정 2013.8.16, 2021.10.20, 2026.7.9>` | 1,508 | 그 조가 개정된 **모든 시점이 누적** |
| `<신설 2026.7.9>` | 459 | 그 항·호가 신설된 시점 |
| `삭제 <2013.6.21>` | 20 | 조가 삭제돼도 **번호는 빈 껍데기로 남는다** (조 번호 재사용 안 함) |

→ 조 번호는 안정적이다. 삭제돼도 사라지지 않으므로 조 단위 비교의 키로 쓸 수 있다.

### 1-3. 부칙 — 누적된다

```
부칙 <제1025호,2013.6.21>     ← 개정 1회 = 부칙 1블록
부칙 <제1030호,2013.8.16>
…
부칙 <제2132호,2026.7.9>      ← 최신 = 이번 개정
```

부칙 블록의 `<제N호,날짜>` 를 파싱하면 **개정 이력 전체**를 본문만으로 복원할 수 있다. 최신 블록이 이번 개정의 시행일·경과조치를 담는다.

⚠️ 부칙은 마지막 조 뒤에 붙으므로 조문 파싱 시 **분리하지 않으면 직전 조의 변경으로 오귀속**된다(`_amend_selfdiff.py` 가 분리 처리).

## 2. 개정의 종류 — 알림 우선순위의 근거

law.go.kr `target=eflaw` 회신 `제개정구분명` 실측 분포(워치리스트 4개 법령의 전 공포 버전, n=331):

| 값 | 건수 | 알림 관점 |
|---|---|---|
| **일부개정** | 250 | 기본 |
| **타법개정** | 71 | **다른 법이 바뀌면서 딸려 수정된 것** — 대개 용어·인용조 정리라 강도를 낮출 수 있다 |
| 제정 | 4 | 최우선 |
| 전부개정 | 4 | **최우선** — 조 번호 체계가 통째로 바뀔 수 있어 조 단위 비교가 무의미해진다 |
| 폐지 | 1 | 최우선 |
| 일괄개정 | 1 | 드묾 |

`현행연혁코드` 3값: **시행예정**(공포됐으나 미시행) · **현행** · **연혁**(더 최신이 시행돼 효력 상실).
→ 개정 감지는 공포 시점이 기준이므로 `target=eflaw` 로 **시행예정까지** 봐야 한다(`target=law` 는 현행만 줘서 놓친다).

## 3. 별표·서식 — 두 함정

### 3-1. ⚠️ `flSeq`(다운로드 링크)는 개정 때 **전량 재발급**된다

같은 개정(`4abdd2a`)에서 첨부파일 블록:

```diff
-  파일링크: …flDownload.do?flSeq=159845891     +  파일링크: …flSeq=166851535
-  파일링크: …flDownload.do?flSeq=159845897     +  파일링크: …flSeq=166852141
-  파일링크: …flDownload.do?flSeq=159845905     +  파일링크: …flSeq=166852149
      (그 법의 별표 전부 — 내용이 안 바뀐 것까지)
```

법령이 새 공포본을 내면 **첨부가 공포본 단위로 통째 재발급**되기 때문이다. 따라서 **`flSeq` 변화를 "별표가 개정됐다"의 신호로 쓰면 전량 오탐**이 된다. 링크는 *어디서 받을지*만 알려줄 뿐 *무엇이 바뀌었는지*는 말하지 않는다.

### 3-2. ⚠️ PDF 해시도 신호가 아니다 — **원본만 봐야 한다**

git 이력 전체의 별첨 변경 유형:

| 유형 | 건수 | 확장자 |
|---|---|---|
| A 신규 | 651 | 혼합 |
| **M 내용 수정** | **21** | **전부 `.pdf`** |
| D 삭제 | 32 | 혼합 |

**원본(hwp/hwpx)의 M은 0건**이다. PDF 는 law.go.kr 이 재생성할 때 생성 타임스탬프 등 메타데이터가 들어가 **내용이 같아도 바이트가 달라진다**. 즉 PDF 해시 변경은 재생성 노이즈일 가능성이 높다.

→ **별표 변경 판정은 원본(hwp/hwpx) 해시로만** 한다. PDF 는 비전 대조·폴백 용도로만 둔다.

### 3-3. 신설 별표는 **가지번호**로 들어온다

`별표번호` + `별표가지번호` 조합. 실측(원자력안전법 시행규칙): 166건 중 **43건이 가지번호 보유**.

```
별표 1의2 · 방사성동위원소등 허가사용자의 방사선안전관리자 인력기준(제68조의4제1항제1호 관련)
별표 4의2 · 원자로조종면허 신체검사 합격기준(제116조의2제3항 관련)
```

기존 별표 사이에 새 별표를 끼워 넣을 때 뒤 번호를 밀지 않으려고 가지번호를 쓴다. 조문의 `제N조의M` 과 같은 원리.

→ **안정적 식별자 = `(모법, 별표구분, 별표번호, 별표가지번호)`**. 파일명은 제목이 손질되면 바뀌므로 키로 부적합하다.

### 3-4. 별표 파일은 법령 개정과 **다른 주기로** 도착한다

2026-07-09 개정으로 신설된 건강진단표 서식이 실제로 들어온 시점:

| 커밋 | 내용 |
|---|---|
| 2026-07-19 `4abdd2a` | 법령 본문 개정 반영 (제121조·MST 변경) |
| **2026-07-26 `8f210cd`** | **서식 파일 2종 신규 추가(A)** ← 일주일 늦게 |

법령 본문과 별표 수집이 같은 CI 회차에 붙지 않는다. 따라서 **"MST 무변경 = 이번 주 아무 일 없음" 은 틀리다** — 별첨은 따로 봐야 한다.

## 4. 미러 재가공의 실체

2026-07-26 커밋(`8f210cd`)은 116줄이 바뀌었으나 법은 그대로였다. 실제 diff:

```diff
-- 별표번호: 0008        ++ 별표번호: '0008'      ← YAML 직렬화 방식 변경(따옴표)
```

legalize-kr 이 frontmatter 직렬화를 바꾼 것이다. **재가공은 본문뿐 아니라 frontmatter 형식으로도 온다** — 그래서 필드 *값* 비교(MST)가 필요하고 텍스트 diff 로는 구별되지 않는다.
